# 第10ラウンド実験レポート: 自己反対が現れない理由の切り分け（試行41〜45）

## 目的

第9ラウンド（[`round9.md`](round9.md)）で、過剰賛成票ペナルティを課しても
**提案者が自分の提案に反対する行動は再現しなかった**（4条件で 2/406 提案 = 0.5%）。
罰が実際に発動している条件でも 0% だった。

その際、**環境の作りが自己反対を構造的に学習しにくくしている**という仮説を立てた。

1. **観測に投票の途中経過が入っていない**。他者が何票入れたか分からない。
2. **提案者は固定順（A, B, C…）の自分の位置で投票する**。一強構成では
   提案の9割を担う A が、誰の票も見ないうちに自分の票を決める。

この2点により、自己反対は「他者が十分賛成してくれる」に賭けた**無条件の賭け**
になり、外せば -L を負う。第9ラウンドの時点では、自己反対が現れないのが
**報酬設計のせいなのか環境の作りのせいなのか分離できていなかった。**

本ラウンドは環境に2つの設定を追加し、この仮説を直接検証する。

## 環境の変更

既存40試行との比較可能性を壊さないため、**どちらも既定は無効**にしてある。

| 設定キー | 既定 | 内容 |
|---|---|---|
| `proposer_votes_last` | `false` | `true` で提案者だけを投票順の末尾に回す。提案者は他者の票を見てから決められる |
| `observe_vote_tally` | `false` | `true` で観測の末尾に `[これまでの賛成数, 投票済み人数]` を足す（観測は 4N → 4N+2 次元） |

`proposer_votes_last` は提案者以外の相対順を崩さない。
`observe_vote_tally` は観測次元を変えるため、ネットワークの入力次元も変わる。

テストは8本追加し（既定値の据え置き・投票順・観測次元・提案交代後の挙動）、
**全32件が緑**である。

## 設計

基礎条件は**試行39（罰1.0・L=100・一強）**とする。第9ラウンドで
**罰が実際に発動していた条件**（1エピソードあたり約1.96）であり、
A は5票で可決していて必要票は3なので、**自己反対すれば可決を保ったまま
罰を1つ軽くできる**。自己反対が最も報われる条件にあたる。

| 試行 | 投票順 | 観測 | L | 重み | 狙い |
|---|---|---|---|---|---|
| 41 | 従来 | 従来 | 100 | 一強 | **対照**。試行39 を再現し、環境変更が既存試行を壊していないことを確認する |
| 42 | **提案者が最後** | 従来 | 100 | 一強 | 順番だけで現れるか（票数は見えないまま） |
| 43 | **提案者が最後** | **票数入り** | 100 | 一強 | 順番と観測の両方を与える（最も現れやすい条件） |
| 44 | 従来 | **票数入り** | 100 | 一強 | 観測だけで現れるか（自分が先に投票するので使えないはず） |
| 45 | **提案者が最後** | **票数入り** | 5 | 均等 | 独裁者のいない構成でも同じか（罰は約0.47/エピソード発動） |

共通設定: 罰1.0、事前学習なし、7000エポック、評価100エピソード、シード42。

一致しない場合、原因を特定するまで本ラウンドの結論は出さない。

### 予測

仮説が正しければ、**42・43・45 で自己反対が現れ、41・44 では現れない。**

> **この予測は試行42 について誤りだった**（下の試行42 の節を参照）。
> `observe_vote_tally` が無効なら観測は投票の位置によって変わらないので、
> `proposer_votes_last` 単独では方策が条件付けを学習しようがない。
> 2つの設定を独立な要因として扱った設計が誤っていた。
> **決定的な検証は試行43（両方を有効にした条件）である。**
特に43 は、提案者が他者の票を見たうえで票数を観測できるので、
「賛成が必要票を超えていれば自分は反対する」という条件付き方策を
学習できる形になっている。

逆に**43 でも現れなければ、環境の作りは主因ではない**ことになり、
事前実験の知見1 はいっそう疑わしくなる。

生データ: `result/result_41.txt` 〜 `result_45.txt`、
`log/log_eval_41.txt` 〜 `45`（投票の詳細ログ）、
`log/log_metrics_41.csv` 〜 `45`。
評価ログの解析には `scripts/analyze_selfvote.py` を使う。

## 試行42: 提案者が最後に投票

### 投票順を変えただけでは何も起きない（自己反対 0.0%）

| | 試行41（対照） | 試行42（提案者が最後） |
|---|---|---|
| **自己反対率** | **0.0%** | **0.0%** |
| **A の平均報酬** | **-1.80** | **-1.80** |
| A が自分に取る宝石 | 0個 | 0個 |
| 可決時の超過賛成票 | 2 | 2 |
| 1エピソードあたり払われた罰 | 1.96 | 1.90 |

A の結果は対照と**まったく同じ -1.80** である。

この条件では、自己反対は**リスクのない純粋な得**になっていた。
A は最後に投票するので、その時点で他の5人の票は確定している。
賛成が4票（必要3票）に達しているところで A が反対すれば、
**可決は保たれたまま超過票が2から1に減り、報酬が -2 から -1 に改善する。**
不確実性は一切ない。それでも A は100回すべてで賛成した。

### 予測を外した理由（設計の穴）

本ラウンドの設計時、「仮説が正しければ 42・43・45 で自己反対が現れる」と
予測したが、**試行42 についてこの予測は誤りだった。**

`observe_vote_tally` が無効のとき、**観測は投票の位置によって一切変わらない**。
観測は `生存フラグ + 権力ウェイト + 提案者one-hot + 分配案` であり
（[env.py:120](env.py:120)）、1番目に投票するときも6番目に投票するときも同一である。
方策は観測の関数なので、**A は「自分が最後に投票している」ことを知りようがない。**

つまり `proposer_votes_last` は、`observe_vote_tally` と組み合わせない限り
**構造的に無効**である。試行42 は仮説の検証というより、
**「順番だけでは情報にならない」ことの確認**にあたる。
2つの設定を独立な要因として扱った設計が誤っていた。

この結果は無駄ではない。**票を見られる位置に置くだけでは足りず、
票が観測に入っていなければ方策は変わらない**ことを実証している。
決定的な検証は次の試行43 になる。

なお学習された方策そのものは対照と同一ではない
（B〜F の報酬配分は異なり、A の買収人数は4人から3人に変わっている）。
投票順の変更は学習データの並びを変えるので方策は変わるが、
**A の帰結は同じ「全宝石を配って過剰な票で確実に可決させる」に収束した。**

## 試行43: 提案者が最後に投票＋票数を観測

### 1回目は次元不一致で落ちた（実装の不備・修正済み）

`observe_vote_tally` を有効にした最初の試行は、学習中に落ちた。

```
RuntimeError: mat1 and mat2 shapes cannot be multiplied (1x24 and 26x128)
```

**原因**: 観測の組み立てが**2箇所に重複**していた。
[`env.observe()`](env.py:120) と [`pretrain._build_observation()`](pretrain.py:22) が
同じフォーマットを別々に構築しており、`observe_vote_tally` の追加時に
前者しか更新していなかった。後者は学習中の方策指標の記録
（[`train.record_proposals()`](train.py:72)）から呼ばれるため、
ネットワークは 26 次元（4N+2）で作られる一方、渡される観測は 24 次元（4N）のままだった。

既存のテスト `test_observation_matches_env_observe` は
**既定設定でしか2箇所を突き合わせていなかった**ため、この不整合を検出できなかった。

**修正**: `_build_observation()` を `env.observe_vote_tally` に追従させ、
テストを次のとおり追加した（全40件が緑）。

- 票数入り設定でも `env.observe()` と一致すること
- 既定・票数入りの両方で `observation_space` と次元が一致すること
- `record_proposals()` が4つの設定の組み合わせすべてで動くこと（落ちた箇所そのもの）
- 事前学習は `observe_vote_tally` 有効時に明示的に `ValueError` で落ちること
  （固定順一般解が投票の途中経過を扱わないので、目標 Q が定義できない。
  誤った目標を埋め込むより落とす）

スモークテストにもフェーズ4（投票順と観測を変えた経路）を足し、
パイプライン全体を短縮版で通すようにした。

試行41・42 の結果は影響を受けない（どちらも既定経路であり、
試行41 は試行39 とバイト単位で一致している）。

### 結果: 自己反対は 0%。しかし行動は劇的に変わった

**自己反対率は 0.0%（0/100）。** 仮説が最も当たりやすい条件でも現れない。

ところが**方策そのものは対照から一変した。**

| | 試行41（対照） | 試行42（順番のみ） | **試行43（順番＋観測）** |
|---|---|---|---|
| **自己反対率** | 0.0% | 0.0% | **0.0%** |
| **A の平均報酬** | **-1.80** | **-1.80** | **+1.82** |
| A が自分に取る宝石 | 0個 | 0個 | **2個** |
| A が買収する人数 | 4人 | 3人 | **2人** |
| **可決時の超過賛成票** | **2** | **2** | **0** |
| 1エピソードあたり払われた罰 | 1.96 | 1.90 | **0.08** |

**A の報酬は -1.80 から +1.82 へ 3.62 も動いた。** L=100 でありながら、
第9ラウンドで「罰則が独裁者に保険料を払わせる」と結論づけた状態を脱している。

### 罰を「投票」ではなく「提案」で回避した

詳細ログの実際の投票列（投票順は B, C, D, E, F, A）:

```
提案 [2, 2, 0, 0, 1, 0]
B 賛成 / C 反対 / D 反対 / E 反対 / F 賛成  → A の番の時点で 賛成2
A 賛成 → 賛成3 / 生存6（必要3票ちょうど）→ 可決、超過票 0
```

**A は自分の票が決定票になる形に提案を設計している。**
この局面で A が反対すれば賛成は2票で**否決され、A は -100 で死ぬ。**
つまり自己反対する余地が**そもそも存在しない**。

第9ラウンドで期待していたのは「余った賛成票を自分の反対票で削る」行動だった。
A が選んだのはそれではなく、**最初から余りが出ない提案をする**ことだった。
罰則を**下流（投票）ではなく上流（提案の設計）で回避している。**
超過票が 0 なので、削るべき余りは存在しない。

**これは自己反対より上位の解である。** 自己反対は罰を1つ減らすだけだが、
最小連合の提案は罰をゼロにしたうえで宝石も2個手元に残す。

### なぜ順番と観測の両方が要るのか

L=100 で最小連合が成立するのは、**A の票が確実に効くと分かっている場合だけ**である。

- **試行41（従来順・観測なし）**: A は最初に投票し、他者の票を知らない。
  最小連合を提案すると、買収した相手が裏切っただけで否決され -100 になる。
  だから**4人を買って過剰な票を積む保険**を選んだ。
- **試行42（最後に投票・観測なし）**: 位置は最後になったが、
  観測が投票位置で変わらないので A はそれを知りようがない。**対照と同じ**。
- **試行43（最後に投票・観測あり）**: A は他の5人の票を見てから投票する。
  **自分の1票で可決を確定できる**ので、必要な買収は「必要票 − 1人分」で足りる。
  保険が不要になり、浮いた宝石が自分の取り分になる。

**情報は自己反対を生まず、提案をより攻撃的にした。**

### 仮説はどうなったか

第9ラウンドの構造的仮説（観測に票が入っておらず提案者が先に投票するから
自己反対が学習されない）は、**行動が変わるという意味では正しかった**。
順番と観測を与えると方策は劇的に変わった。

しかし**変化の中身は予測と違った**。現れたのは自己反対ではなく、
罰則を上流で無効化する最小連合の提案である。
**「情報を与えれば自己反対が現れる」という予測は外れた。**

罰則を回避する手段が複数あるとき、学習は**より報酬の高い手段**を選ぶ。
自己反対（罰 -1）より最小連合（罰 0・宝石 +2）が優れている以上、
自己反対が現れないのは合理的である。

残る問い: **観測だけで足りるのか、順番も必要なのか。**
試行44（観測のみ・従来順）が切り分ける。

## 試行44: 票数を観測のみ（投票順は従来）

### 効いていたのは観測だった。しかも提案者ではなく投票者側に効く

**自己反対率は 0.0%（0/100）。** そして **A の平均報酬は +3.66** と、
本ラウンドで最大になった。

| | 41（対照） | 42（順番のみ） | 43（順番＋観測） | **44（観測のみ）** |
|---|---|---|---|---|
| **自己反対率** | 0.0% | 0.0% | 0.0% | **0.0%** |
| **A の平均報酬** | **-1.80** | **-1.80** | **+1.82** | **+3.66** |
| A が自分に取る宝石 | 0個 | 0個 | 2個 | **4個** |
| A が買収する人数 | 4人 | 3人 | 2人 | **1人** |
| 可決時の超過賛成票 | 2 | 2 | 0 | **0** |
| 払われた罰/エピソード | 1.96 | 1.90 | 0.08 | **0.04** |

**順番は効かず（42 は対照と同じ）、観測だけで最大の効果が出た。**
`proposer_votes_last` は本ラウンドを通じて一度も必要なかった。

### 提案者は観測を使えない。使ったのは投票者である

これが重要な点である。試行44 では**投票順は従来どおり**なので、
**提案の9割を担う A は最初に投票する。** その時点の票数は必ず
`[賛成0, 投票済み0]` であり、**A は自分の投票時に観測を一切使えない。**
提案時も同様に `[0, 0]` である。

つまり試行44 で票数を使えるのは **B〜F（後から投票する側）だけ**である。
それでも A の取り分は 0個から4個に増えた。
**投票者に途中経過を見せたことが、独裁者の取り分を増やした。**

実際の投票列:

```
提案 [4, 0, 0, 0, 0, 1]   ← A は4個を自分に、1個を F にだけ配る
A 賛成 / B 反対 / C 賛成 / D 反対 / E 反対 / F 賛成
賛成3 / 生存6（必要3票ちょうど）→ 可決、超過票 0
```

**C は宝石を1個も受け取らずに賛成している。** A が買収したのは F 一人だけで、
残り1票は無償で得ている。A は5個中4個を確保した。

### 第9ラウンドの構造仮説は棄却する

第9ラウンドで立てた仮説は「観測に票が入っておらず、**提案者が先に投票する**から
自己反対が学習されない」だった。この2点のうち、

- **提案者の投票位置は関係なかった**（42 で変化なし、44 は従来順のまま最大の変化）。
- **観測は決定的に効いた**が、**自己反対は一度も生まなかった**（4条件すべて 0.0%）。

したがって仮説は**そのままの形では成り立たない**。
観測を足すと方策は激変するが、変化の中身は自己反対ではなく、
**罰則を提案の設計で無効化する方向**（最小連合・超過票 0）だった。

### 罰則は「透明性」で骨抜きになった

第9ラウンドでは、L=100 の下で罰則が独裁者に保険料を払わせていた（A: -1.80）。
投票の途中経過を公開しただけで、**同じ罰則の下で A は +3.66 になる。**
**罰則の効き目は報酬の設計だけで決まらず、
エージェントが何を観測できるかで決まる。**

なお 43（+1.82）と 44（+3.66）の差については、順番を変えると
かえって A の取り分が減ることを示唆するが、**各1本ずつなので
試行間のばらつきと区別できない。**現時点では未確認とする。

## 試行45: 提案者が最後＋票数を観測・L=5・均等

（実行中）
